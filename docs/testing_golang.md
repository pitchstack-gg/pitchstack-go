# Testing - Golang

This documents how testing for Go is covered in this repository.

## Mocks

Mocks are autogenerated using mockery v3. Interfaces that should be mocked are outlined in the `.mockery.yaml` configuration file.

Targets in the Makefile will include commands for generating and updating mocks as needed.

When using these mocks, the expector `mock.EXPECT().Method()` should be used for tests.

## Unit Tests

Unit tests in this package use the built-in `testing` package from Go's standard library. Test files are located in the same directory as the code they test and have a `_test.go` suffix.

In addition, the `testify` package is used for more simpler assertion and requirement statements.

### General Tests

Tests should be structured so that each public method has a single test function that consists of several sub-tests. A test files should be created to mirror the logic files. Sub-tests names should follow gherkin syntax, where the name describes the intent of the text. This should follow a pattern like "when given x, then y".

Parameterized tests should be used when acceptable when numerous inputs would be helpful to fully exercise the method being tested.

### Database Tests

Tests that would evaluate code with direct interaction with the database should not mock these calls, and instead use real database connections. Presently, this repository uses a PostgreSQL database for most primary data stores.

This database should be spun up using the testcontainer library. The database should have the tables outlined in the `db/migrations` directory applied before running the tests.
